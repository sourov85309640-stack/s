# Common rules for IMPLEMENT agents (read after BRIEF.md and SPEC_v32.md)

1. Own only the files named in your task. The lead owns base.css, core.js, boot.js, header.js, index.html, build.py, swap-map.txt. Section partials are in src/sections/NAME.html (start from what is there: it is the old dark markup, rewrite it freely).
2. Read src/core.js (window.RW API) and src/base.css (tokens, buttons, edges, utilities) before writing code. Use the tokens; do not invent new colours (tints of the palette are fine, define them as custom properties at the top of your own CSS file, scoped to your section).
3. JS: one IIFE per file. Register features with RW.add('name', fn, {motion:true}) for anything animated, and RW.add('name', fn) for behaviour that must work under reduced motion / data-motion="off" too (buttons, carousels, switches, forms). Never touch window.scroll position on touch devices except in response to a tap. Use RW.mm (gsap.matchMedia) for pinned/flow splits and return a cleanup. Use RW.tick for continuous loops (shared rAF) and pause them with RW.onView when offscreen.
4. CSS: the no-JS / reduced-motion / data-motion="off" state is the FINAL state. Only hide things for animation from JS (gsap.set) or under `html.has-motion`. Hover inside @media (hover:hover). Press :active scale .97. Focus: :focus-visible outline 3px copper with offset (base.css already does this globally; do not remove outlines).
5. Accessibility: semantic HTML, headings in order (h2 per section, h3 inside), buttons for actions and links for navigation, aria-pressed / aria-expanded / aria-selected where it applies, every image alt (decorative = alt="" or aria-hidden), 44px targets, colour contrast 4.5:1 for text (copper #985632 is fine on paper/warm/white; check sand and sky; copper tint is never text).
6. Copy: plain UK English, no em dashes or en dashes as dashes, no scarcity, no invented claims or numbers (sample numbers must be data-sample), company neutral. Things the owner must confirm: data-confirm="...".
7. Self-test before you report: `cd /home/user/s/work/v31 && mkdir -p out && python3 build.py out/<tag>.html` (build must print no ERROR lines caused by your files), then a Playwright script using tools/qa_lib.py (`sys.path.insert(0,'/home/user/s/work/v31/tools')`) at 1440x900 and 390x844 (mobile, touch) at least, plus reduced motion and data-motion=off: console clean, no horizontal overflow (qa_lib.overflow), nothing stuck hidden after scrolling through (qa_lib.hidden_text), screenshots of your section(s) that you LOOK at with the Read tool and judge honestly against "would this be on a $20,000 site?". Fix what you see. Iterate at least twice.
8. Report (under 400 words): what you built (bullets), files, SWAP-MAP lines for anything the owner must replace, test evidence, known issues, REQUEST TO LEAD.
